# Active Context

## Текущий фокус

Проект находится на стадии рабочего прототипа. Канонический прогресс по `Project Deliverables` — 55%: есть базовый показ атома, выбор всех элементов H-Og, черновая `s/p/d/f`-визуализация, Orbit focus, стартовый выбор элемента, переключение `EN/RU` и достаточная для текущего scope читаемость орбиталей. Образовательный слой исключен из scope по решению пользователя; дальше остаются адаптивность, тесты, performance, CI/CD, деплой и новое расширение функционала для молекул/соединений.

## Активная задача

- Переделка 3D-визуализации атома: электронная оболочка должна подразделяться на энергетические уровни, уровни — на подуровни `s/p/d/f`, подуровни — на отдельные орбитали с электронами.
- Memory Bank создан и синхронизирован.
- `docs/README.md` создан как источник архитектурной правды.
- Next.js приложение создано на Bun.
- Реализованы 3D-сцена, локальные данные H-Og, выбор элемента и информационная панель.
- UI-слой переведен на `Button`, `Card`, `Badge` из `src/components/ui/`.
- Реализован расчет электронной конфигурации, подуровней и орбиталей в `src/lib/electronConfiguration.ts`.
- Облака вокруг электронов удалены; реализованы разные траектории орбиталей в `AtomScene`.
- `AtomScene` переделан на отображение занятых `spdf`-орбиталей как траекторий движения электронов; облака орбиталей удалены.
- Добавляется режим фокуса орбиталей: ручной выбор орбитали, приглушение остальных траекторий, замедление неактивных электронов и пошаговое заполнение.
- Memory Bank приведен к правилам `AGENTS.md`: канонический процент считается только по `Project Deliverables`, используются допустимые статусы deliverables, обязательные файлы присутствуют.
- Текущая задача: исправлены учебные траектории `d` и `f` в `AtomScene`; вместо одинаковых/условных кривых используются отдельные варианты `dxy/dyz/dxz/dx²-y²/dz²` и семь различимых `f`-траекторий.
- `OrbitalFocusPanel` расширен: теперь можно выбрать не только весь подуровень вроде `3d`, но и конкретную заполненную ориентацию/траекторию внутри него, например `dxy`, `dyz`, `dxz`, `dx²-y²`, `dz²`.
- UX выбора орбиталей переделан: длинный список убран из правой панели, вместо него компактная карточка текущего фокуса и кнопка `Choose`, открывающая overlay-карту уровней/подуровней/ориентаций.
- После UX-уточнения overlay-карта заменена на компактный dropdown-интерфейс: `Subshell` выбирает подуровень, `Orientation` выбирает `All` или конкретную ориентацию внутри выбранного подуровня.
- Поведение `Reset` изменено: сброс выбора больше не автофокусирует последний заполненный подуровень, а возвращает общий вид всех орбиталей без приглушения.
- В Overview-режиме движение электронов замедлено, dropdown выбора орбитали визуально стилизован, а `InfoPanel`/секция Selected element уплотнены и получили прокрутку контейнера, чтобы не обрезаться в правой панели.
- Добавлен полноэкранный режим просмотра атома: кнопка `Fullscreen` открывает overlay со сценой без правой панели, `Exit` возвращает обычную компоновку.
- Fullscreen уточнен: иконка открытия находится в правом верхнем углу зоны просмотра, fullscreen overlay занимает весь viewport, а выход выполняется иконкой minimize поверх сцены.
- `f`-траектории переделаны с условных декоративных многопетлевых кривых на более узнаваемые учебные лепестковые формы для семи стандартных `f`-вариантов: `fxyz`, `fz(x²-y²)`, `fx(x²-3y²)`, `fy(3x²-y²)`, `fxz²`, `fyz²`, `fz³`.
- После сверки с базовым определением атомных орбиталей как real combinations of spherical harmonics, `f`-траектории уточнены: контуры теперь строятся от соответствующих real harmonic-полиномов, чтобы сохранять научную симметрию, а не просто декоративные петли.
- Плоские `f`-орбитали `fx(x²-3y²)` и `fy(3x²-y²)` исправлены: отрицательные лепестки harmonic-функции теперь отображаются как отдельные противоположные лепестки через модуль радиуса, а не схлопываются в трехлистный клевер.
- Завитки на стыке вытянутых `dz²` и `fz³`-траекторий убраны: кривая теперь явно замыкается последней точкой `2π`, а `CatmullRomCurve3` больше не делает автоматическое сглаженное замыкание.
- Последняя попытка перестроить `f`-траектории по типам 8/6/2-like лепестковости отклонена пользователем и откатана к предыдущей harmonic-версии.
- Шестилепестковые `f`-формы визуально разведены: вторая форма получает дополнительный поворот, а обе формы получили небольшой базовый радиус и ripple, чтобы стилистически ближе совпадать с остальными `f`-контурами и не накладываться друг на друга.
- Вытянутая `fz³`-траектория упрощена и сглажена: вместо перегруженной harmonic-формы используется аккуратный осевой контур с мягкой поясной петлей.
- После уточнения пользователя `fz³` сбалансирована между слишком сложной и слишком ровной формой: возвращена harmonic-модуляция оси и поясной петли, но без прежней перегруженности.
- Выбор элемента теперь открывается сразу при первом заходе на сайт: overlay периодической таблицы стартует в открытом состоянии, сохраняя Hydrogen как элемент по умолчанию до выбора пользователя.
- Для устранения hydration warning от browser extension-инъекций вроде Dark Reader на корневой `<html>` добавлен `suppressHydrationWarning`.
- Overlay выбора элемента уплотнен: периодическая таблица масштабируется по высоте viewport, карточки элементов и отступы уменьшены, чтобы таблица помещалась на экран без обязательной прокрутки.

- Читаемость ячеек периодической таблицы улучшена: фон элементов затемнен и отделен от backdrop рамкой/тенью, названия элементов увеличены и усилены по контрасту.

## Решения

- Источник требований: `docs/PRD.md`.
- Источник архитектурной правды: `docs/README.md`.
- MVP реализуется без backend, только frontend/client-side.
- Для MVP используется локальный TypeScript-модуль данных `src/data/elements.ts`.
- Состояние выбранного элемента хранится в `src/app/page.tsx` через `useState`.
- Ручного состояния orbital view нет: уровни, подуровни, орбитали и электроны выводятся автоматически из числа электронов элемента.
- Стартовый UX ведет пользователя сначала к выбору элемента: `ElementSelector` открыт при загрузке главной страницы.
- Язык интерфейса хранится локально в состоянии главной страницы и пробрасывается в UI-компоненты через props; backend/i18n framework пока не используется.
- shadcn/ui используется как локальные primitives, добавленные в `src/components/ui/`, с конфигурацией `components.json`.
- `d/f`-орбитали остаются учебными траекториями движения электронов, а не облаками вероятности; формы должны различать ориентации и типы орбиталей, чтобы не вводить пользователя в заблуждение одинаковыми кривыми.

## Неопределенности

- Канонический процент выполнения считается только по `Project Deliverables` и сейчас составляет 55%; образовательный слой больше не входит в scope проекта.
- Для молекул/соединений пока не определены модель данных, UX и режимы визуализации — это будущий крупный scope change.
